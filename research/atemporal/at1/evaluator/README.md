# AT-1 Agent 4: adversarial evaluator

Independent evaluator for AT-1 (aien-dev/omega#371). It reads only the frozen contracts
`AT1_CASE_V1`, `AT1_RESULT_V1` and `AT0_RESULT_V2` (identical at arch commits `cbe4c8e`,
`81047f5` and `ea91d7c`) and `AT1_SPEC` / `AT1_CHARTER`; it never reads the oracle's
(Agent 2) or the engine's (Agent 3) code. PASS here means conformance to those
documents and nothing else; no statement about physics is made or implied.

Rust 2021, std only, no Cargo, one `rustc` call; the gate controls need a C11 compiler.
Portable to macOS arm64 (Apple clang 17, GNU make 3.81, rustc 1.97.1): POSIX sh, no
GNU-make-4 features, digests computed in code. No Python.

## Run lines

```sh
make            # build/at1-eval
make test       # unit tests, selftest, corpus byte check, mutant receipt, isolation-gate controls
make corpus     # regenerate cases/ (corpus-check must then report 0 differ)

# qualify the candidates (templates: {case} = case path, {out} = result path; without {out}, stdout)
sh run.sh '<engine> {case} {out}' '<oracle> {case} {out}' [cases] [out-dir] [hidden-dir]

# isolation gate G2 on the candidates' compute objects (not on static executables, see limits)
sh gates/isolation.sh ./build/at1-eval <object.o>...

# single tools
./build/at1-eval case <file> [--why]        # codec: AT1_CASE_OK or one stderr line, exit 2
./build/at1-eval shadow <case>              # exact (or double-double) model values
./build/at1-eval verify --case <case> <result>              # exit 0 PASS, 1 FAIL, 3 INCONCLUSIVE
./build/at1-eval verify --case <case> --oracle-record <rec>
./build/at1-eval splice <engine-result> <oracle-record> <out>
```

A dry run with the built-in honest synthetic engine and oracle (all gates PASS):
`B=$PWD/build/at1-eval; sh run.sh "$B synth-engine {case} {out}" "$B synth-oracle {case} {out}"`.

## Design

- **Codec.** Independent `AT1_CASE_V1` parser; every refusal row must give exactly its code
  (one stderr line, exit 2) from my codec, the engine and the oracle (gate G1). The KAT
  `at1-kat-rotated-level-n4` reproduces case_file_sha256 `76e282fe...9ba4`, case_id
  `890980a4...25f1` and acceptance_id `d63246c3...4d8f` (selftest).
- **Shadow model.** Exact rational arithmetic when every phase is a quarter turn, otherwise
  double-double with a claimed bound of 1e-24. It reproduces the spec 13.2 hand tables
  exactly and the 13.3 deviation maxima (selftest, 549 assertions).
- **Runner splice.** The engine writes engine lines with `reference_*` undefined; the
  splice copies all four reference families from the oracle record, binds oracle
  provenance, re-judges checks 1 to 12 per `AT0_RESULT_V2` sections 4 and 5 and reseals
  `verdict_id` and `evidence_sha256`. An oracle ERROR record gives ERROR `ORACLE_UNAVAILABLE`.
- **Verify.** Re-derives every check, the outcome, the codes and the expectation from the
  written values and compares; decides check 3 (trivial kernel) from the exact shadow, as
  AT-0 did, while the splice judges on the engine's own claim; compares every engine and
  reference value with the shadow (beyond bound plus tolerance is a FAIL; beyond only its
  own bound is a FAIL for RIGOROUS, INCONCLUSIVE for ESTIMATED, nothing for NONE).
- **Per-case table.** `qualify` writes `TABLE.tsv` (PASS / FAIL / INDETERMINATE per case;
  INCONCLUSIVE findings map to INDETERMINATE) and `VERDICT_IDS.tsv`, prints the gate lines
  G1, G3, G4, G5 and T9 (engine run twice with another time zone and an extra environment
  variable), and exits 0 only when all pass. G2 is `gates/isolation.sh`; G6 and G7 belong
  to Agents 6 and 7.

### Finding codes

| Code | Severity | Meaning |
|---|---|---|
| E4-PARSE | FAIL | result not byte-exact `AT1_RESULT_V1` |
| E4-VERDICT-ID, E4-EVIDENCE-DIGEST | FAIL | identity digest does not recompute |
| E4-CASE-SHA, E4-CASE-BINDING | FAIL | copied case lines do not rebuild the case file, or ids do not match the case |
| E4-PROV-ORACLE-RECORD, -ORACLE-IS-ENGINE, -NONE, -TIME-ORDER | FAIL | provenance rule broken |
| E4-PROV-CONTRACT-UNKNOWN, E4-PROV-DIRTY-TREE | INCONCLUSIVE | contract commit off the allowlist, or dirty tree |
| E4-PLACEHOLDER-SHAPE, E4-RUN-NOT-COMPLETED, E4-UNDEFINED-DISCIPLINE, E4-TRIVIAL-SHAPE, E4-ORACLE-TRIVIAL, E4-LABEL-RULE, E4-BOUND-NONE-NONZERO | FAIL | shape rules of the result contract |
| E4-CHECK-MISMATCH, -OUTCOME-MISMATCH, -CODES-MISMATCH, -EXPECTATION-MISMATCH | FAIL | written verdict differs from the re-derived one |
| E4-EXPECTATION-NOT-MET | FAIL | candidate's result does not meet the case's expectation |
| E4-EXPECTATION-INDETERMINATE | INCONCLUSIVE | the only discrepancy is `PRECISION_INSUFFICIENT` |
| E4-SHADOW-KERNEL-DIM, -TRIVIAL, -POVM, -CLOCK, -LABEL, -PAULI | FAIL | engine value disagrees with the shadow |
| E4-ORACLE-CLOCK, -LABEL, -INTERACTING, -IDEAL | FAIL | spliced reference disagrees with the shadow (gate G3) |
| E4-BOUND-CLAIM-FALSE | FAIL | RIGOROUS bound does not cover the shadow difference |
| E4-BOUND-ESTIMATE-LOW | INCONCLUSIVE | ESTIMATED bound does not cover the shadow difference |

## Hidden set

`at1-eval hidden-gen <seed> <dir>` draws 27 cases (families F0 to F8 of spec 13.1 item 7,
index mod 9) from a SHA-256 counter-mode stream keyed by a private 256-bit seed; a draw is
kept only if its honest verdict has the family's intended codes and it meets the spec 8.3
margin rule. Only the commitment is in the repository (`HIDDEN_COMMITMENT.txt`, procedure of
spec 12.3 item 3). At reveal, `run.sh` recomputes the commitment before running the cases.
Agent 7 keeps its own, separate hidden set.

## Limits

1. Isolation is procedural on one host and one account: the hidden-set digest proves the
   identity of the files later revealed, not that nobody read them.
2. The gate scans compute objects. Static executables contain libc's own `svc` and clock
   code, so apply it to the candidates' object files or compute-only archives.
3. The x86-64 instruction scan is a byte-pattern scan and can report false positives in
   data inside executable sections; the aarch64 scan decodes aligned words.
4. The shadow's double-double path (non-quarter-turn phases) is not exact; it claims 1e-24,
   far inside every tolerance in the corpus, and is checked against the exact path in selftest.
5. ESTIMATED bounds that miss the shadow give INCONCLUSIVE, not FAIL. `E4-BOUND-NONE-NONZERO`
   applies to engine lines only; reference lines inherit the oracle's bound semantics.
6. Check 2 aggregates over references as well as engine values, as `AT0_RESULT_V2` section 4
   reads; `PRECISION_INSUFFICIENT` from an engine label is read from engine lines only.
7. The hidden-set seed is passed on the command line (visible to local process listings
   while the generator runs, about 0.1 s).
8. No real engine or oracle existed on any remote branch when this was built; the
   qualification so far ran against the synthetic candidates only.
