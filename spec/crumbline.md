# Crumbline adapter (Omega as a Crumb v1 learner)

Crumbline is the AIEN training curriculum of unlabeled input/output
observations. Its contracts, generators, sealed verifier, mixer, trace schema,
promotion ladder and ledger live in the `crumbs` crate
(aien-dev/aien-sovereign-core, `crates/crumbs`, see its `SPEC.md`). This
repository implements only the consumer adapter.

## What Omega receives

`build/crumbline-learner` is a separate executable. It speaks the crumbs
learner protocol v1 on stdin/stdout and links only learner-side code:

| Linked | Not linked |
|---|---|
| Crumb v1 visible reader (`src/crumbline/cl_crumb.c`) | any generator, sealed record, held-out set or label |
| program / realize / verify stack, synthesis vocabulary | physics, NVRM, gate suites, evidence tooling |
| OmegaLibrary + Crumbline search (`cl_program.c`, `cl_search.c`) | |

Everything the learner can know arrives as protocol frames: visible crumb
bytes, a one-byte verdict per submission, and admitted operations (a CPG1
program, an opaque reference and a scope in bits).

## Loop

```text
CRUMB (visible bytes)
  -> cl_crumb_decode (strict; one input lane, one output lane supported)
  -> bank = omega_synth_base_prim_defs() + OmegaLibrary entries whose scope covers the inputs
  -> level-by-level composition search, observational-equivalence pruning
     over visible inputs + 32 public probes
  -> visible fit -> omega_program_verify (V0 + V2) + native vs reference differential
  -> ambiguity scan (keep looking for behaviourally different rival fits)
  -> SUBMIT as CPG1 -> sealed verifier -> VERDICT byte
     reject: recorded as an event, search continues
  -> no exact fit: best partial fit may be submitted as a robust guess
ADMIT -> cl_library_admit: build, verify, omega_library_insert (receipt binds op_ref + program)
```

`omega_synthesize` is untouched: the M9 gates pin its enumeration order. The
base vocabulary is shared through `omega_synth_base_prim_defs()`.

## Tests

`make test-crumbline` decodes the committed conformance vectors (one per
registered crumbs family, generated by `crumbs vectors`), rejects malformed
inputs, and checks that the learner binary carries no sealed-side symbols.
The protocol, boundary and learning gates run from the crumbs side:
`crumbs gates --learner build/crumbline-learner`.
