## Findings
1. MINOR: RESULT.md "Not bias or autocorrelation: both passed" is overstated. Lag-1 passes (0.094) but the reported-only Ljung-Box Q10 is 151.1 (M0) and 350.4 (M1); the chi-square 5% cutoff for 10 dof is about 18.3. Innovations are strongly serially correlated beyond lag 1. That points to dynamics/model misspecification, so "wrong noise shape, not a wrong mean" is not established by the evidence. Both Q10 values are in the receipt but not mentioned.
2. MINOR: "Not quantization: only 2.8% of innovations exactly zero" is a weak argument. Zero innovation needs the filter estimate to land exactly on a 100 mC grid value, which almost never happens with a smoothing filter, so 2.8% says little. The raw one-step changes are exactly zero 32.7% of the time and |change|<=100 mC 49.4% of the time. Quantization is still very probably irrelevant (sd of change is 1159 mC, 12x the 100 mC step), but for that reason, not the stated one.
3. MINOR: "Heavy-tailed" is supported for the marginal one-step changes but does not separate heavy tails from a mixture over load phases or level-dependent variance (regime switching, a class the protocol lists). One-step changes: n=2008, sd 1158.8 mC, kurtosis 8.40 (excess 5.40), median |change| 200 mC (Gaussian with same sd: 782), p80 1100, p95 2600 (Gaussian 2271), p99 4300 (Gaussian 2985), max 7100. RESULT.md hedges ("possible switching"), so this is a wording caution, not an error.
4. NIT: Quarters are split by logical-time span (30..2008), giving n=495/495/494/495. A simple equal-count split gives 494/495/495/495 and Q1 = 0.8947. Either way Q1 < 0.90, so the quarter_1 failure is not sensitive to this choice.
5. NIT: The receipt's `fit_run_path` is the relative path; a fresh est_fit run writes the absolute path (different params digest if rerun from another directory). The recorded params digest is not reproducible byte for byte unless fit is run from the repo root with a relative path. Numbers are identical.
6. NIT: Interpretations doc was committed in 44f591b, after the freeze commit f96dc97 but before the recorded run. It states it changes no band/grid/model. I found no threshold-relevant tool change: diff f96dc97..44f591b touches only src/estimation, tools, tests, mk and the interpretations doc; HEAD vs 44f591b differs only by receipt files. Frozen protocol doc sha matches its constant. Interpretation 1 (burn-in counted from the prior, 29 innovations dropped after it) is a reading that decides n=1979; it is stated, and the alternative would change nothing material.
7. NIT: Disclosure in protocol section 1 says B was recorded before the workstream and was described only descriptively (line counts, gap, range, 100 mC steps) by a survey worker. So B is "not examined", not blind. RESULT.md does not repeat this caveat. Single execution is consistent with git history (one recorded commit, no prior receipts in git), but I cannot prove from files alone that no other run on B happened outside git. Run B tests in test_est_tools use a synthetic directory named with B's id, not B itself.

No BLOCKER or MAJOR found.
