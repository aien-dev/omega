# OSH conformance vectors

Status: v1 DRAFT with the ABI. Expected outputs were authored from `../OSH_PLATFORM_ABI.md`; no implementation has run them yet (spec section 14, item 6). Inputs are generated by `../tools/make-vectors.sh`; `expected.txt` is committed by hand.

## Files per vector `vNNN`

- `vNNN.in`: the exact input bytes handed to the core, newline-terminated unless the vector says otherwise. May contain NUL and bytes >= 0x80.
- `vNNN.env` (optional): answers to variable requests, one per line, raw bytes to end of line (a value cannot contain a newline). `NAME=VALUE` sets a variable. Lines starting with `@` set specials: `@status=N` is the value of `$?` for every request, `@arg0=` to `@arg9=` set positional parameters (the number of `@argK` lines present, counting from `@arg1` with no gaps, is `$#`). A name with no line is unset.

The harness never executes pipelines. After each `PIPELINE_READY` it records the request, then calls `expand_run` again, treating `$?` as the fixed `@status` (default 0).

## expected.txt line grammar

```
<vector> ok [lex_resumes=N] | P<i> conn=<0-3> | C<j> b=<0-6> argv=<q>,<q>... as=<NAME>=<q>,... rd=<K><fd>:<target>,...
<vector> refuse <code> <NAME> off=<byte offset>
<vector> more
```

- A pipeline is `P<i>`; its commands follow as `C<j>` in order, each preceded by ` | `. Lists of argv, assignments and redirections are comma separated; an empty list is written as nothing after `=`.
- `<q>` is a double-quoted byte string; `\"`, `\\`, `\xHH` escape `"`, `\` and any byte outside 0x20 to 0x7E. `"a"*1100` means 1100 repetitions.
- Redirection `<K>` is `IN`, `OUT`, `APPEND` or `DUP`; `<fd>` the redirected descriptor; `<target>` a `<q>`, or for `DUP` the source descriptor number.
- `more` means the final call returned `NEED_MORE_INPUT` with no further input available.
- `lex_resumes=N` is the exact number of `BUDGET_EXHAUSTED` returns the lexer gave before `PHASE_DONE`.
- A core conforms when every line matches byte for byte. Refusal offsets follow spec section 5.4.

## Local additions (not yet in aien-protocols)

v016 to v020 were added in omega PR #336 for the codes 236 `GROUP`, 246 `BRACE_EXPANSION` and 247 `POSITIONAL_RANGE`, which the ABI draft does not number yet (it reserves 246 to 255). They should go upstream with the ABI amendment.

## Bash-verified vectors (omega PR #336 review fixes)

`bash_vectors.tsv` holds 52 lexer vectors whose expectations come from real GNU bash 5.2, not from the reference tokenizer. Columns (TAB separated): id, input, expect, equiv. `bash_verify.sh` runs both the input and its continuation-free equivalent (or, when equiv is `-`, the script rendered from the expected tokens) under bash and requires identical transcripts (stdout, stderr, files written); the result is recorded in `bash_verified.log` (first line: the bash version, 5.2.21 when written). `make osh-bash-verify` runs it. The lexer driver then checks the lexer against the same expect column and also lexes the equivalent script, so the OSC lexer, the C reference and bash are three separate oracles for backslash-newline handling.

Findings pinned here: backslash-newline is removed before the next byte is classified, mid-operator (`|\<nl>|` is `||`, `a>\<nl>>f` is `>>`, `2\<nl>>f` redirects fd 2, `1\<nl>2>f` is fd 12), after `$` (`$\<nl>$`, `"$\<nl>(`, `$\<nl>{`), in tilde and brace detection, inside double quotes, and not inside single quotes. A backslash in a comment is literal: `# c\<nl>e b` runs `e b`. `x+=1` is an append assignment and `$_` the last-argument parameter; both are refused (248 `APPEND_ASSIGN`, 225 `SPECIAL_PARAM`).

New local code 249 `APPEND_ASSIGN` (248 is SYNTAX_EOF in the parser unit) is not in the ABI draft yet (it reserves 246 to 255); it goes upstream with 236, 246 and 247. A final lone backslash waits for the next byte (status 100, the backslash is not consumed) unless the host sets the lexer cell S_EOI (28), when it is a literal backslash.
